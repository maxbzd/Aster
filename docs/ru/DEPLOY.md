# Публикация сайта и серверные ключи

[English](../DEPLOY.md)

Aster — статическое приложение: папку `dist/` можно выложить на любой хостинг статики по HTTPS (Cloudflare Workers/Pages, Vercel, Netlify, GitHub Pages). Серверные возможности (ключи нейросетей, синхронизация, MCP, TickTick) необязательны и работают как Supabase Edge Functions.

## Как опубликовать

```bash
npm install
npm run build        # результат в dist/
```

**Cloudflare Workers** (репозиторий настроен под него): `wrangler.jsonc` отдаёт `dist/` как статику с запасным переходом на `index.html`. Выберите своё имя воркера в файле и выполните `npx wrangler login`, затем `npx wrangler deploy`.

Чтобы сайт обновлялся при каждом пуше, подключите свой форк в панели Cloudflare: Workers & Pages → ваш воркер → Settings → Builds → репозиторий и ветка, Build command `npm run build`, Deploy command `npx wrangler deploy`. Имя воркера в панели должно совпадать с `name` в `wrangler.jsonc`. GitHub Actions в репозитории только проверяет код, а не публикует.

**Любой другой хостинг:** соберите и загрузите `dist/`. Адреса вида `/#/people` обычно не требуют особых настроек.

## Серверные ключи (чтобы не вводить их в приложении)

Ключи нейросетей и распознавания речи лежат в секретах Supabase Edge Function `ai` (код — `supabase/functions/ai`). Приложение входит к ней сессией облачного аккаунта; в браузер ключи не попадают. Для этого приложение нужно собрать с адресом вашего проекта Supabase (`VITE_SUPABASE_URL`, `VITE_SUPABASE_KEY`, см. `.env.example`) и применить `supabase/migrations/*.sql`.

Секреты задаются в панели Supabase: **Edge Functions → Secrets** → Add new secret:

| Секрет | Зачем | Обязательно |
|---|---|---|
| `ALLOWED_EMAILS` | почты владельцев через запятую; только они могут пользоваться ключами | **да**: пустой список закрывает доступ всем |
| `ALLOWED_ORIGINS` | адрес сайта, например `https://aster.example.com` (несколько — через запятую) | **да**: без него браузер получит отказ |
| `GATEWAY_API_KEY`, `GATEWAY_BASE_URL`, `GATEWAY_MODELS` | любой OpenAI-совместимый шлюз (OpenRouter, LiteLLM, Ollama, свой). `GATEWAY_BASE_URL` — с версией, например `https://openrouter.ai/api/v1`; `GATEWAY_MODELS` — id моделей через запятую, которые покажет приложение | достаточно одного провайдера |
| `GEMINI_API_KEY` | Google Gemini (есть бесплатный тариф) | достаточно одного провайдера |
| `GROQ_API_KEY` | Groq (есть бесплатный тариф) | достаточно одного провайдера |
| `ANTHROPIC_API_KEY` | Claude напрямую | достаточно одного провайдера |
| `DEEPGRAM_API_KEY` | ключ Deepgram: распознавание речи Nova-3 с метками говорящих и подсказками имён из вашей сети (в приоритете над `STT_API_KEY`) | нет |
| `DEEPGRAM_BASE_URL` | адрес Deepgram, если нужен европейский: `https://api.eu.deepgram.com` | нет |
| `STT_API_KEY` | запасной вариант распознавания: ключ OpenAI или Groq | нет |
| `STT_BASE_URL` | адрес сервера распознавания, если не OpenAI (например `https://api.groq.com/openai/v1`) | нет |

После сохранения: войдите в облачный аккаунт со своей почтой, затем Астра → режим **«Сервер»** и выберите модель; распознавание речи — Астра → «Расшифровка записей» → «Ключ на сервере». Появится «✓ Серверный ключ подключён». Секреты меняются без перезапуска и без деплоя сайта.

Как это защищено:
- ключ уходит только к выбранному провайдеру из функции, браузер видит лишь ответ;
- запрос должен нести сессию аккаунта (платформа проверяет подпись, функция — что почта подтверждена и есть в `ALLOWED_EMAILS`): посторонний, даже зарегистрировавшийся, получает 403;
- запросы с чужих сайтов отклоняются (`ALLOWED_ORIGINS`);
- пропускаются только допустимые модели, ответ до 20 000 токенов; выполнение кода, файлы, пакетная обработка закрыты;
- лимит 40 запросов в минуту на аккаунт (распознавание — 20), размер запроса до 2 МБ (аудио — до 25 МБ);
- ключ утёк или тратится странно: замените секрет в панели Supabase и отзовите старый у провайдера, приложение менять не нужно.

Бесплатные тарифы некоторых провайдеров используют данные для обучения, а условия различаются по регионам. Если не хотите отдавать лишнего, в настройках Астры выключите «Передавать заметки и историю»: телефоны и почты из карточек не отправляются в любом случае.

Исходник функции — `supabase/functions/ai/handler.ts`, тесты — `tests/api/ai-function.test.ts`.

## Обязательно в Supabase

- **Authentication → Providers → Email:** включено подтверждение почты. После создания своего аккаунта выключите **Allow new users to sign up**, если проект только для вас: иначе любой сможет завести аккаунт.
- **Authentication → URL Configuration:** Site URL — адрес вашего сайта, и тот же адрес в Redirect URLs (письма подтверждения и сброса пароля).
- **Authentication → Password security:** включить проверку утёкших паролей (Leaked password protection).

## Заголовки безопасности

`public/_headers` задаёт политику содержимого (скрипты только свои, соединения только со своим сайтом, Supabase, Anthropic, OpenAI и Groq), запрет встраивания в чужие страницы, HSTS и запрет доступа к геолокации. Cloudflare и Netlify читают этот файл как есть; на другом хостинге перенесите заголовки в его настройки. Если нужен другой шлюз (режим «Свой ключ») или сервер распознавания, добавьте его адрес в `connect-src`.

## Если что-то не работает

- Cloudflare → Workers & Pages → ваш воркер → Deployments / Builds: лог сборки.
- Проверка серверной функции: `npm test` (тесты `tests/api/ai-function.test.ts`).
- Ручная публикация: `npm run build`, затем `npx wrangler deploy` (нужен `wrangler login`).
- Прокси для Vercel (`api/claude`) — для тех, кто предпочитает его Supabase (режим «Прокси»).

## Сравнение моделей

В приложении: Астра → режим «Сервер» → «Сравнить модели на тестовых задачах» (экран `/eval`). Прогоняет 14 выдуманных задач (разбор заметок, диалог по записям, поиск по сети, черновики, бриф) через выбранные модели и показывает, где какая ошиблась; отчёт скачивается файлом. Ключи берутся с сервера, настоящие данные не используются. То же из терминала: `EVAL_API_KEY=... EVAL_BASE_URL=... EVAL_MODELS=... npm run eval` (значения можно положить в `.env.eval`).
