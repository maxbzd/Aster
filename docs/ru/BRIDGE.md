# Мост между приложениями: Aster ↔ Орбита

[English](../BRIDGE.md)

Aster и его родственное приложение **Орбита** (задачи, обязательства, решения и дневник; тоже открытый проект, [github.com/maxbzd/Orbita](https://github.com/maxbzd/Orbita)) — два отдельных приложения с **раздельными базами** (разные проекты Supabase) обмениваются данными по подключению «как календарь»: в одном приложении показываешь код, в другом вставляешь — и данные ходят сами. Пароль второго аккаунта не нужен.

Если вы пользуетесь только Aster, мост можно игнорировать: он скрыт, пока не настроено облако, и ничего не делает, пока вы не свяжете приложения. Общий код (`src/bridge/protocol|pairing|peer|own|connect|match|cycle.ts`) в обоих приложениях **одинаковый**: меняешь в одном — обнови копию в другом.

## Что передаётся

| Вид данных | Направление | Что получается |
| --- | --- | --- |
| `person`, `person_stats` | в обе | список людей и сводка (Aster: последний контакт, близость; Орбита: упоминания, открытые обязательства) |
| связи людей | в обе | «человек в Aster = человек в Орбите»; одинаковое полное имя связывается само, остальное — по подтверждению |
| `commitment` | Орбита → Aster | обязательство становится напоминанием (у связанного человека) |
| `commitment_state` | Aster → Орбита | «выполнено/открыто» по напоминанию возвращается в обязательство; побеждает более поздняя правка |
| `capture` | Орбита → Aster | запись о встрече — **предложение** добавить в хронологию человека (резюме и день, без полного текста) |
| `fact` | Орбита → Aster | факт о человеке — предложение добавить в карточку |

Не передаётся: ключи ИИ и настройки, настроение и состояние, полный текст записей, демо-данные. Каждый вид данных владелец может выключить в настройках моста.

## Как это работает

```
Aster                                                        Орбита
 локальные данные ─collect→ bridge_feed (проект Aster)  ←pull(token)─  читает Орбита
 читает Aster  ─pull(token)→ bridge_feed (проект Орбиты) ←collect─ локальные данные
```

1. **Витрина.** Каждое приложение публикует у себя таблицу `bridge_feed` (нейтральные записи: `entity`, `key`, `data`, `updated_ms`). Пишет в неё только вошедший владелец, функцией `bridge_publish`.
2. **Подключение по коду.** Приложение A: `bridge_create_offer` → одноразовый код на 10 минут. Приложение B: заводит у себя ключ (`bridge_register`, хранится хэш), обменивает код на ключ A (`bridge_accept`), записывает его (`bridge_complete`). Код — `bridge1.<base64url{url, key, code, label}>`.
3. **Чтение.** Другая сторона читает витрину анонимно функцией `bridge_pull(token, after, limit)`: сервер сверяет хэш ключа и отдаёт только разрешённые владельцем виды данных (`scopes`). Ключ — 256 бит случайности, привязан к одному аккаунту и отзывается: `bridge_disconnect` у себя или `bridge_drop` со стороны другого.
4. **Цикл** (`cycle.ts`): опубликовать изменённое (по отпечаткам) → забрать чужое с курсором (с запасом назад) → применить адаптером (идемпотентно, без дублей: у отражений детерминированные id вроде `bridge-<ключ>`). Запускается при входе, раз в минуту, при возвращении в приложение, после правок.
5. **Связи людей** хранятся на сервере в `bridge_links` (общие для устройств). Приложение, которое связало людей, сообщает об этом через поле `peerRef` в записи `person`; `peerRef: null` — явный разрыв (после него автосвязь пару не возвращает).
6. **Адаптеры** (`asterAdapter.ts`, `orbitaAdapter.ts`) знают модель своего приложения; всё остальное общее.

## Конфликты

- Обязательство: заголовок, срок, человек — за Орбитой; «выполнено» можно отметить в любом приложении, побеждает более поздняя правка (`updated_ms`).
- Удалил напоминание-отражение в Aster — оно не вернётся (`settings.bridgeHandled`).
- Удалено в источнике — отражение удаляется.

## Безопасность

- Анонимны только три функции: `bridge_accept`, `bridge_pull`, `bridge_drop`; все проверяют ключ или код внутри. Остальные требуют входа.
- Таблицы закрыты для прямого чтения/записи (RLS и отсутствие прав): всё через функции.
- В Орбите `index.html` должен разрешать обращения к адресу Supabase Aster (`connect-src`); в Aster `public/_headers` разрешает `*.supabase.co`.
- Нужны вход в облако в **обоих** приложениях: подключения и связи живут в ваших аккаунтах.

## Подключение (для человека)

1. Войди в облако и в Aster, и в Орбите (разные аккаунты Supabase — почту и пароль можно использовать одни и те же).
2. В Aster: Профиль → «Приложение «Орбита»» → «Показать код».
3. В Орбите: Настройки → «Приложения» → «Ввести код» → вставь.
4. Проверь «Люди»: подтверди неоднозначные совпадения.

## Настройка серверов

Применить `supabase/migrations/…_bridge.sql` в **обоих** проектах Supabase (SQL Editor или `supabase db push`). Файл один и тот же.

## Проверки

- `npm test` — ядро (код, подключение, цикл, конфликты) и адаптеры на «проектах» в памяти с теми же правилами, что в SQL.
- SQL проверялся в откатываемой транзакции: одноразовость кода, хэш ключа, фильтр разрешений, отзыв, изоляция пользователей, запрет прямого доступа.
- Живой прогон на двух настоящих проектах: см. шапку `tests/e2e/bridge.live.test.ts`.
