# Связка с TickTick

[English](../TICKTICK.md)

Напоминания из Aster появляются в TickTick, а отметка «выполнено» работает в обе стороны.

- **Новое в приложении → TickTick:** в течение минуты задача появляется во «Входящих» TickTick: с названием, сроком и пометкой, откуда она и по какому человеку.
- **Выполнено в приложении → закрывается в TickTick.**
- **Выполнено в TickTick → отмечается в приложении** (проверка раз в минуту, пока приложение открыто).
- **Задачи из TickTick в приложения не переносятся.** Приложение узнаёт о TickTick только то, что задача, которую оно само отправило, закрыта.
- Если задачу удалить в TickTick, она больше не опрашивается и заново не создаётся. Если удалить в приложении, в TickTick она остаётся.

Работает, пока приложение открыто (вкладка или установленное приложение): синхронизация идёт из самого приложения, раз в минуту, при возврате на вкладку и через пару секунд после любой правки.

## Настройка (один раз)

1. Откройте <https://developer.ticktick.com> → **Manage Apps** → **New App**. Название любое, например «Aster». В поле **OAuth redirect URL** впишите адрес функции своего проекта:
   `https://<ref-вашего-проекта>.supabase.co/functions/v1/ticktick/callback`
2. Скопируйте **Client ID** и **Client Secret** приложения.
3. В Supabase → **Edge Functions → Secrets** добавьте:
   - `TICKTICK_CLIENT_ID` — Client ID;
   - `TICKTICK_CLIENT_SECRET` — Client Secret.

   Секреты `ALLOWED_EMAILS` и `ALLOWED_ORIGINS` общие для проекта (см. [DEPLOY.md](DEPLOY.md)): функция `ticktick` использует те же.
4. В приложении: Профиль → «TickTick». Нажмите «Подключить TickTick», разрешите доступ и вернитесь.

Нужен вход в облачный аккаунт в приложении: связь идёт через него.

## Как это устроено

- Edge Function `ticktick` (`supabase/functions/ticktick`), без входа по JWT на уровне платформы (нужен маршрут возврата из TickTick), но все остальные маршруты сами проверяют сессию Supabase и список `ALLOWED_EMAILS`.
- Токен TickTick и связи «запись приложения ↔ задача TickTick» лежат в таблицах `ticktick_tokens` и `ticktick_links`. Права на них закрыты для всех, кроме самой функции.
- Возврат из TickTick защищён подписанным `state` (HMAC на секрете приложения TickTick, живёт 10 минут) и проверкой адреса возврата по `ALLOWED_ORIGINS`.
- Ключ `aster:reminder:<id>` связывает запись с задачей. Связь занимается до создания задачи, поэтому два устройства одновременно не создадут дубль.
- Токен TickTick живёт около полугода. Когда он закончится, в настройках появится «Доступ закончился», достаточно подключить заново.

## Если что-то не работает

- В настройках «TickTick ещё не настроен на сервере»: не заданы секреты (п. 3).
- После согласия вернулись, а подключения нет: адрес возврата в приложении TickTick должен совпадать с адресом из п. 1 до символа.
- Задача не появилась: откройте «Синхронизировать» в настройках и посмотрите красное сообщение; логи функции — в Supabase → Edge Functions → ticktick → Logs.
